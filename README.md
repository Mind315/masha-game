# ТЗ — обучающая браузерная игра для детей 4+

## 1. Общая концепция

Рабочее название: **«Остров открытий»**

Игра представляет собой красочный интерактивный обучающий мир для детей примерно от 4 лет.

Основное управление — **мышь**.

Ребёнок исследует карту, открывает различные локации и выполняет короткие мини-игры. За успешно выполненное задание получает **звезду**.

Основной принцип:

> Ребёнок должен воспринимать игру как приключение, а не как учебник.

Интерфейс должен быть максимально простым:

- крупные элементы;
- минимум текста;
- много анимаций;
- понятные изображения;
- озвучивание действий;
- отсутствие сложных меню;
- отсутствие необходимости пользоваться клавиатурой.

# 2. Структура игры

На данный момент реализуется первый мир:

```text
ОСТРОВ
│
├── 🌲 ЛЕС
│   │
│   ├── 1. Счёт до 15
│   ├── 2. Фигуры
│   ├── 3. Цвета
│   ├── 4. Память
│   ├── 5. Поиск предметов
│   ├── 6. Большой/маленький
│   ├── 7. Что лишнее?
│   ├── 8. Продолжи последовательность
│   ├── 9. Найди пару
│   └── 10. Собери лес
│
├── 🚜 ФЕРМА — будущий уровень
├── 🏙️ ГОРОД — будущий уровень
├── 🌊 МОРЕ — будущий уровень
└── 🚀 КОСМОС — будущий уровень
```

На первом этапе разрабатывается только **Лес**.

---

# 3. Главный экран — карта острова

После запуска игры ребёнок попадает на большую красочную карту.

На карте находятся различные локации.

Первая доступная локация:

## 🌲 Лес

Лес должен быть визуально выделен и интерактивен.

При наведении мыши:

- лёгкое увеличение;
- подсветка;
- персонаж может произнести:
  > «Лес! Давай пойдём исследовать лес!»

При клике:

**открывается карта леса.**

Другие локации пока заблокированы или отображаются как будущие территории.

Например:

> 🔒 «Скоро здесь будет ферма!»

---

# 4. Карта леса

После входа в лес ребёнок видит большую красивую карту.

На ней расположены **10 игровых точек**.

Примерная схема:

```text
                    🌲
             [2. Фигуры]
                    │
       🍄           │           🐿️
 [5. Поиск] ──── [ЛЕС] ──── [6. Размер]
       │                         │
       │                         │
 [4. Память]                [7. Лишний]
       │                         │
       🌳──── [1. Счёт] ────────┘

              [8. Последовательность]

                    [9. Пары]

                   [10. Собери лес]
```

Геометрия может быть изменена. Главное — чтобы это выглядело как **реальная карта**, а не меню из десяти кнопок.

Каждая игра имеет:

- собственную маленькую локацию;
- персонажа;
- иконку;
- анимацию;
- название;
- статус прохождения.

---

# 5. Система звёзд

Каждая мини-игра является отдельным заданием.

За прохождение ребёнок получает:

⭐ **1 звезду**

После выполнения игры точка на карте меняется:

```text
До:

🌳
❔

После:

🌳
⭐
```

При повторном посещении можно показывать:

> ⭐ Задание выполнено!

В первой версии:

**1 игра = 1 звезда.**

Максимум за лес:

**10 ⭐**

# 6. Прогресс

На главном экране должен присутствовать персонаж/аватар ребёнка.

## Аватар

Предусмотреть специальное место для фотографии ребёнка.

Например:

```text
┌──────────────────────┐
│                      │
│       [ФОТО]         │
│                      │
│      Мой прогресс    │
│                      │
│       ⭐⭐⭐⭐⭐       │
│       ⭐⭐⭐⭐⭐       │
│                      │
│       7 / 10         │
└──────────────────────┘
```

Фото должно быть круглым или с мягкими скруглёнными углами.

В коде предусмотреть простой способ заменить изображение:

```text
/assets/avatar.jpg
```

Родитель сможет просто заменить файл фотографии.

---

# 7. Панель прогресса

На карте леса в верхней части экрана:

```text
👧 [Аватар]

Мои звёзды ⭐ 6 / 10
```

Также можно отображать:

```text
🌲 ЛЕС

⭐⭐⭐⭐⭐⭐☆☆☆☆

6 из 10 заданий выполнено
```

Прогресс должен сохраняться в браузере.

Для первой версии использовать:

```javascript
localStorage
```

Например:

```text
forest_game_1 = completed
forest_game_2 = completed
forest_game_3 = false
...
```

После закрытия браузера прогресс не должен пропадать.

# 8. Озвучивание

**Каждый интерактивный элемент должен иметь озвучку.**

Основной голос:

**женский, доброжелательный, спокойный, игровой.**

Использовать Web Speech API или подготовленные аудиофайлы.

Предпочтительно архитектурно сделать отдельный сервис:

```text
speechManager
```

Например:

```javascript
speak("Давай посчитаем яблоки!");
```

## Что озвучивается

### Кнопки

При наведении:

> «Назад»

При клике:

> «Возвращаемся на остров»

### Игровые объекты

Например, ребёнок нажимает на яблоко:

> «Яблоко»

Нажимает на красный круг:

> «Красный круг»

### Правильный ответ

> «Правильно! Молодец!»

или:

> «У тебя получилось!»

### Ошибка

Никакого резкого «Неправильно!».

Например:

> «Попробуй ещё раз.»

или:

> «Хм... Давай посмотрим внимательно.»

### Завершение игры

> «Ура! Ты выполнил задание!»

После этого появляется:

⭐

и небольшая праздничная анимация.

# 9. Игра №1 — «Считаем в лесу»

## Цель

Научить ребёнка считать предметы от **1 до 15**.

## Механика

На экране появляются лесные предметы:

- 🍎 яблоки
- 🍄 грибы
- 🌰 жёлуди
- 🌸 цветы
- 🐿️ белки

Например:

> «Помоги белочке собрать **7 желудей**.»

На экране разбросано 10–15 предметов.

Ребёнок должен нажимать на нужное количество.

Каждый клик:

- предмет перемещается в корзинку;
- произносится число;
- запускается маленькая анимация.

Например:

> «Один!»

> «Два!»

> «Три!»

...

> «Семь!»

После достижения нужного количества:

🎉 успех.

## Диапазон

Уровни постепенно:

```text
1–3
1–5
1–7
1–10
1–12
1–15
```

Цель — постепенно довести ребёнка до уверенного счёта до 15.

# 12. Игра №4 — «Лесная память»

Простая игра на развитие памяти.

## Первый вариант

На экране:

```text
🐰 🍎 🦊 🌸
```

Через 2–3 секунды предметы закрываются.

Появляются карточки:

```text
❓ ❓ ❓ ❓
```

Ребёнок открывает карточки и должен найти одинаковые изображения.

## Начальный уровень

4 карточки.

## Затем

- 6 карточек;
- 8 карточек;
- 10 карточек;
- 12 карточек.

Важно не делать игру слишком сложной для 4-летнего ребёнка.

---

# 13. Игра №5 — «Найди предмет»

## Цель

Развитие внимания и визуального поиска.

На экране большая иллюстрация леса.

Например:

```text
🌳 🌲 🌳 🐿️ 🍄 🌸 🦔 🍎 🪵
```

Персонаж говорит:

> «Найди гриб! 🍄»

Ребёнок должен найти его среди объектов.

После клика:

🍄 увеличивается и подпрыгивает.

Персонаж:

> «Вот он! Ты нашёл гриб!»

## Постепенное усложнение

Сначала:

**1 цель + мало объектов**

Потом:

**1 цель + много объектов**

Затем:

**2 цели**

Например:

> «Найди гриб и яблоко.»

---

# 14. Игра №6 — «Большой или маленький?»

Развитие сравнения размеров.

На экране:

🐻 большой медведь  
🐰 маленький кролик

Задание:

> «Покажи большого зверя.»

Ребёнок выбирает.

Следующий вариант:

> «Покажи маленький гриб.»

Позже:

> «Поставь большой предмет рядом с маленьким.»

---

# 15. Игра №7 — «Что лишнее?»

Развитие классификации и логического мышления.

Например:

```text
🍎 🍐 🍊 🚗
```

Персонаж:

> «Что здесь лишнее?»

Ребёнок нажимает 🚗.

Другой вариант:

```text
🐶 🐱 🐰 🍎
```

Правильный ответ — яблоко.

Важно делать задания очень простыми и очевидными.

---

# 16. Игра №8 — «Продолжи ряд»

Развитие логики и понимания последовательностей.

Например:

```text
🔴 🔵 🔴 🔵 ❓
```

Нужно выбрать:

🔴

Другой вариант:

```text
🍎 🍌 🍎 🍌 ❓
```

Ребёнок выбирает 🍎.

Для 4 лет начинать с простых последовательностей:

```text
ABAB
ABAB
```

Позже:

```text
AAB
AAB
```

# 17. Игра №9 — «Найди пару»

Отличается от обычной памяти.

На экране предметы:

```text
🐰       🐰
🍎       🍌
🌸       🌸
```

Задание:

> «Найди двух одинаковых зайчиков.»

Ребёнок должен выбрать пару.

Можно добавить механику перетаскивания мышью на более позднем этапе.

Для первой версии достаточно кликов.

---

# 18. Игра №10 — «Собери лес»

Это финальная игра уровня.

Ребёнок помогает восстановить маленький участок леса.

На экране пустая поляна.

Появляются предметы:

- 🌳 дерево
- 🌸 цветок
- 🍄 гриб
- 🪨 камень
- 🐿️ белка

Ребёнок должен разместить их в подходящие места.

Например:

- дерево → в землю;
- цветок → на поляну;
- камень → рядом с деревом;
- белка → на дерево.

Каждый правильный объект оживляет сцену.

После завершения:

- 🌳 деревья оживают;
- 🐦 прилетают птицы;
- 🦋 появляются бабочки;
- ☀️ появляется солнце.

Персонаж говорит:

> «Ты помог лесу! Какой красивый он стал!»

После этого ребёнок получает **последнюю звезду**.

🎉

> «Ты исследовал весь лес!»

🎁

# 20. Визуальный стиль

Стиль:

**яркий, добрый, мультяшный, современный 2D.**

Не использовать слишком много мелких деталей.

Для 4-летнего ребёнка:

- большие кнопки;
- большие персонажи;
- крупные предметы;
- высокий контраст;
- минимум текста;
- плавные анимации;
- отсутствие пугающих элементов.

Желательно сделать интерфейс похожим на **детскую интерактивную книжку**, а не на компьютерную игру для взрослых.

# 21. Анимации

Практически каждое действие должно иметь визуальную реакцию.

## Наведение мыши

```text
объект → слегка увеличивается
```

## Клик

```text
объект → небольшая анимация
```

## Правильный ответ

```text
объект → подпрыгивает
⭐ → появляется
конфетти → короткая анимация
```

## Ошибка

Не использовать красный экран или негативные звуки.

Объект слегка покачивается.

Голос:

> «Попробуй ещё раз.»

# 28. Архитектура мини-игр

Каждая игра должна быть независимым модулем.

У каждой игры единый интерфейс:

```javascript
startGame()
```

```javascript
finishGame()
```

```javascript
resetGame()
```

Например:

```javascript
CountingGame.start();
```

После успешного завершения:

```javascript
Progress.complete("counting");
```

После этого состояние сохраняется в `localStorage`.

Пример состояния:

```json
{
  "forest": {
    "counting": true,
    "shapes": true,
    "colors": false,
    "memory": false,
    "search": false,
    "size": false,
    "oddOneOut": false,
    "sequence": false,
    "pairs": false,
    "forest": false
  }
}
```

# 29. Принцип прогресса

Важно: **не привязывать прогресс к одному прохождению.**

Если ребёнок выполнил игру один раз:

```text
⭐
```

она считается открытой навсегда.

При повторном прохождении:

- звезда не исчезает;
- ребёнок может играть снова;
- можно генерировать новые задания.

Например, сегодня:

> «Найди 5 яблок.»

А завтра:

> «Найди 8 яблок.»

Это позволит избежать ощущения, что ребёнок просто один раз прошёл игру и всё закончилось.

---

# 30. Генерация заданий

По возможности задания должны генерироваться случайно.

Для счёта:

```javascript
target = random(1, 15);
```

Для цветов:

```javascript
color = random(colors);
```

Для фигур:

```javascript
shape = random(shapes);
```

Для поиска:

```javascript
target = random(objects);
```

Благодаря этому одна и та же игра не будет каждый раз проходиться одинаково.

---

# 31. Важное правило для озвучки

Все названия объектов должны храниться централизованно.

Например:

```javascript
{
    id: "apple",
    name: "Яблоко",
    voice: "Яблоко"
}
```

Не нужно прописывать голосовые фразы непосредственно в HTML.

Должна существовать единая система:

```javascript
Speech.say("Яблоко");
```

или:

```javascript
Speech.sayObject("apple");
```

Это позволит в будущем заменить синтез речи на профессиональные заранее записанные голоса без переписывания всей игры.

---

# 32. Главное требование к игре

Игра должна ощущаться как **живой мир**.

Не:

> «Выберите правильный ответ.»

А:

> 🐰 «Ой! Я потерял свои яблоки! Поможешь мне их найти?»

Не:

> «Найдите треугольник.»

А:

> 🦊 «Посмотри! Где спрятался треугольник?»

Не:

> «Задание выполнено.»

А:

> 🎉 «Ура! Ты помог мне! Получай звёздочку!»

# 34. Рекомендуемая архитектура будущих миров

Карту и систему прогресса сразу проектировать не только под лес, а под систему:

```text
World → Location → Game
```

Пример:

```text
Island
 ├── Forest
 │    ├── Counting
 │    ├── Shapes
 │    ├── Colors
 │    └── ...
 │
 ├── Farm
 │    ├── ...
 │
 ├── City
 │    ├── ...
 │
 └── Space
      ├── ...
```

После завершения леса добавление **фермы, города, моря и космоса** должно заключаться в добавлении нового мира и его игр, а не в переписывании всей архитектуры.

Озвучка также должна быть отдельным слоем, чтобы впоследствии можно было перейти с браузерного синтезированного голоса на настоящие записанные реплики без изменения кода мини-игр.
